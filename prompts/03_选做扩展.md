# 选做扩展提示词

下面是后续开发任务，并非本期基础原型已经实现的能力。先跑通基础流程，每次只增加一个功能，做好后单独验收。

### 一次给三个建议

```text
在当前项目加入三个候选回复：自然、简短、轻松。基于同一段已确认的聊天生成，不新增我的承诺或经历。我点哪个就复制哪个，并有明确反馈。先做最小可用版本，用虚构聊天演示，再复测现有快捷键和粘贴流程。
```

### 联系人表达偏好 选做

```text
在现有助手加入联系人偏好，我能填写关系、表达偏好和背景，并能查看、修改、删除。只有当前聊天标题与一个联系人明确且唯一匹配时才使用；不明确就用通用规则，不能沿用上一人的资料。生成的建议不能自动记成我说过的话。先用两个虚构联系人演示隔离和删除，再实际试用。此项完成后单独验收。
```

联系人偏好属于后续开发任务；这套提示词尚未在另一台电脑从零完整复跑。模型服务以自己的账户规则为准。


## 更多创作参考

以下保留早期需求模板里的扩展想法，可择一改写后继续开发；不是原始聊天全文。

**越用越像我：**

```text
加入“学习我的修改”：当我主动保存自己修改后的建议时，提取可查看、可撤销的表达偏好。先显示学到了什么，再由我确认保存。只有联系人明确时才归到该联系人，否则保存在我指定的通用风格里。不要把修改稿当成已经发送的消息。用虚构例子演示保存前后的差异。
```

**我说个意思，它帮我发起话题：**

```text
加入“主动开口”模式：我输入一个粗略想法，例如“想问客户下周有没有时间”，它结合当前联系人偏好，生成自然的开场问话。保留原意，不替我承诺时间、价格或进度。做好后和原来的“回复对方”模式分别测试。
```

**有其他想法时，套用这一条：**

```text
我想在现有应用里加【用一句话描述新功能】。请先做最小可用版本，直接在当前项目实现，保留已经跑通的快捷读取和复制流程；若已实现联系人偏好，也保留隔离规则。完成后让我实际试用，再根据我的反馈调整，并更新构建记录。
```
